01One engine · Binance kits

Markets disagree. That disagreement is the signal.

The exchange prices leverage. The chain prices holders. The prediction market prices the outcome. The crowd prices the story. Single-domain agents read one and call it truth. Optic reads them together and reports the gap — on Binance, through Binance.

01 — READ

Every Binance market at once

Spot + perps through the Binance MCP Server, onchain through Binance Web3, outcomes through Binance Wallet prediction markets, attention through the social-hype board — one query fans out across all of them.

02 — RESEARCH

The homework behind the numbers

Live web research — form, catalysts, macro — so a read is never just a data printout. Sources cited on every brief.

03 — SCORE

Score the gap

A 0–100 gap score, a decisive verdict line, and a shareable card. Observational language, lint-gated in code — never a trade instruction.

04 — ACT

Hand over the ticket

Decided? Optic constructs the exact order — market, outcome, size — as the caller's own Binance rails: a confirm-before-execute MCP order, or the two baw prediction trade commands for the Agentic Wallet. Optic signs nothing.

04For agents & builders

Your agent can read the gap in one request.

Plain HTTP, JSON in, JSON out. Install the skill and any Agent OS client — Claude Code, Codex, ChatGPT, OpenClaw — can call it by name. Then act on Binance's own rails.

quickstartPOST · JSON
# 1 — a full cross-venue read
curl -s -X POST https://optic-binance-production.up.railway.app/v1/read \
  -H "Content-Type: application/json" -d '{"query":"BTC"}'

# 2 — turn a decision into Agentic Wallet commands (Optic never signs)
curl -s -X POST …/v1/ticket -H "Content-Type: application/json" \
  -d '{"query":"Fed decision in September no change","side":"yes","usdt":25}'

# 3 — or run it as an MCP server, beside Binance's own
claude mcp add binance-mcp-server --transport http https://agent.binance.com/mcp/agentic
claude mcp add optic --transport http https://optic-binance-production.up.railway.app/mcp

Binance's MCP Server only accepts its own approved agent clients, so Optic never asks to hold your session — it joins the one you already have. Your agent pulls the exchange leg with its Binance tools and passes it into optic_read; Optic reports that leg as binance-mcp because that is where it came from. Every order Optic constructs is still confirmed by you, in your own sub-account or Agentic Wallet.
